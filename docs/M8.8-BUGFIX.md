# M8.8 — Bugfix & stabilisasi (M8.4 follow-up)

Audit codebase (quest/work/schedule flow + silent failure points) dan rencana
perbaikan. Milestone kecil, fokus pada bug yang sudah dilaporkan user plus bug
silent yang ditemukan saat audit.

## Bug yang dilaporkan user

### B1 — Progress kerja tidak jalan meski pekerjaan berhasil
- **Gejala**: menyelesaikan minigame kerja, progress/rank tidak bertambah.
- **Root cause (suspected)**: `WorkClient.claimReward` memanggil `claimWork(...)`
  (server action) dan hanya memperbarui state kalau `result.ok`. Kegagalan
  (rate limit / sesi invalid / DB) ditelan `console.error` tanpa feedback ke
  user → progress terlihat "tidak jalan". Selain itu `jobStats` dibaca ulang
  dari `/api/affection` hanya saat mount; kalau fetch awal gagal, state kosong.
- **Fix**: tampilkan error ke user (toast), retry otomatis 1x, dan fallback
  refresh state dari server setelah klaim.

### B2 — Tidak bisa mengambil hadiah misi di /schedule
- **Gejala**: tombol "Klaim" misi gagal (silent, tidak ada feedback).
- **Root cause (confirmed)**: `claimQuestRewardServer` menyisipkan baris klaim
  baru dengan `action = quest.targetAction` (sama dengan baris progress). Tabel
  `dailyQuests` punya unique index `uq_daily_quests_user_date_action` pada
  `(user_id, date, action)` → insert klaim **gagal constraint violation** →
  route 500 → client silent. Mock test tidak mereplikasi constraint, jadi
  lolos.
- **Fix**: ubah constraint menjadi dua partial unique index:
  - `(userId, date, action) WHERE questId IS NULL` (satu baris progress per aksi)
  - `(userId, date, questId) WHERE questId IS NOT NULL` (idempoten klaim)
  Migrasi baru + update `claimQuestRewardServer`. Juga filter `questId IS NULL`
  pada query progress (hindari count dari baris klaim) dan tambah `ORDER BY`.

## Silent bug tambahan (ditemukan saat audit)

### B3 — Event `daily_quests_updated` tidak ada listener
- `recordQuestAction` (client) dispatch event `daily_quests_updated`, tapi
  `ScheduleClient` tidak mendengarkannya → progress tidak refresh optimistik
  tanpa reload halaman. Kode localStorage di `recordQuestAction` adalah dead
  code (server = otoritas) dan menyesatkan.
- **Fix**: tambah `useEffect` listener di `ScheduleClient` yang fetch state
  server; hapus dead code localStorage (atau tandai deprecated).

### B4 — QuestTracker deferred → visit action bisa tidak tercatat
- `QuestTracker` dimuat via `requestIdleCallback` (timeout 2500ms). Jika user
  navigasi < 2.5s, aksi `visit_*` (termasuk `visit_work`) tidak pernah
  tercatat → progress "tidak jalan".
- **Fix**: catat `visit_*` secara sinkron pada mount route (fetch ringan) atau
  turunkan timeout; pertahankan deferred hanya untuk bundle.

### B5 — `getQuestDayState` progress count tidak filter baris klaim
- `rows[0]?.count` tanpa `questId IS NULL` / `ORDER BY` → count bisa diambil
  dari baris klaim (ketika sudah ada). Setelah B2 diperbaiki, lebih aman
  filter `questId IS NULL`.
- **Fix**: filter + ORDER BY createdAt.

### B6 — `handleClaimQuest` / `handleClaimMilestone` swallow error
- Kegagalan fetch (network/500) hanya `console.error` → user tidak tahu.
- **Fix**: tampilkan toast/Livia reaction, retry.

### B7 — `recordQuestAction` fire-and-forget tanpa retry
- Jika fetch gagal (offline), aksi hilang (server = otoritas).
- **Fix**: retry 1x dengan backoff; atau antrian lokal. Minimal: retry 1x.

## Rencana perbaikan (milestone kecil)

1. Migrasi DB: ganti unique index `uq_daily_quests_user_date_action` → dua
   partial unique index (lihat B2). Generate + `db:migrate`.
2. `quests.server.ts`: update `claimQuestRewardServer` (insert tetap, tapi
   constraint baru memungkinkan); filter progress `questId IS NULL` + ORDER BY.
3. `ScheduleClient`: tambah listener `daily_quests_updated` → fetch state;
   tampilkan error pada claim (toast).
4. `WorkClient`: tampilkan error + retry pada `claimWork` gagal.
5. `QuestTracker`: catat visit action lebih awal (turunkan timeout / sync).
6. `quests.ts`: hapus dead code localStorage (atau tandai deprecated).
7. Test: tambah test yang mereplikasi constraint (mock harus throw pada
   duplicate) + test claim sukses/ganda dengan data real-shape.
